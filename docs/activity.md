# 活动服务与任务执行

本文说明 AutoBiubiu 如何读取官方活动、提交任务与抽奖请求，以及任务队列的执行与结果核对流程。客户端侧的连接与加速命令见 [biubiu 客户端协议](protocol.md)。

## 活动链接与页面

活动链接限定为：

```text
https://www.biubiu001.com/activity/activityTemplate?activityUuid=<活动编号>
```

页面公开信息可通过 HTTPS 读取；服务端渲染 HTML 中的 `window.__INITIAL_STATE__` 包含 `actInfo`、`actConfig` 和 `activityUuid`。活动中心列表由 biubiu 客户端读取，见 [客户端命令](protocol.md#客户端命令)。

导入链接与“更新公开内容”只读取公开规则并保存到本机，不连接客户端，也不读取账号进度。账号进度需要连接客户端后通过“刷新活动与进度”读取。

## 活动请求

| 路径 | 用途 |
| --- | --- |
| `/activity/activityTemplate` | 读取活动详情与任务状态 |
| `/activity/activityTemplate/reportTaskFinish` | 提交任务完成核验 |
| `/activity/activityTemplate/draw` | 使用已有抽奖次数 |
| `/activity/activityTemplate/getActiveAwardDetail` | 查询奖品详情 |
| `/activity/activityTemplate/myprizes` | 读取官方中奖记录 |

账号态请求使用客户端现有会话 Cookie、`csrfToken` 对应的 `x-csrf-token`、User-Agent、Origin 与 Referer。Cookie 值按 Chromium 返回的原值发送，兼容逗号、空格、引号、反斜杠及 UTF-8，不做二次编码；控制字符与分号仍会被拦截，域名、路径和有效期过滤保持生效。应用不保存账号密码或客户端登录令牌。远端业务状态与网络传输结果分开处理：如果写请求超时、响应格式无效或结果未知，会保留待核对状态，不自动重试；确认服务器状态后再执行重新读取。

## 任务范围

自动计划仅处理 PC 客户端中可识别的 `type: 7` 加速时长任务，包括明确要求 PS/Xbox 等平台的主机任务；邀请、访问页面、绑定、手机加速及游戏内时间只展示说明。任务状态取自服务端字段，历史累计 `finishCount` 不作为当日完成依据。

所有游戏统一按任务说明识别平台与时长，不因游戏名称或历史共享标记改变任务分类。计划、手动映射保存、旧队列执行及实际领取入口均使用通用的手机端任务排除规则，手机端任务即使已有 `status: 2` 也不会触发自动领取。任务编号、服务端状态和待核对记录保留。

映射时长范围为 1–1440 分钟，以 0.5 分钟为步长；区服可留空，使用上次区服或第一个可用区服。

## 执行流程

1. 按所选活动生成计划，同一平台、游戏与区服合并。核对账号和客户端状态后，先处理无需加速的领取和已有抽奖次数。
2. 刷新官方会员到期时间。有有效会员时按原计划执行；会员已过期或无法确认时，先尝试处于明确限免时段的游戏，其次尝试官方免费目录中的游戏。处理完一组免费候选后，再刷新会员到期时间；确认有新的有效时长后继续其余任务，否则本轮不启动免费资格未确认的游戏。
3. 每 5 秒读取实际加速状态，只累计经过验证的有效区间；不把睡眠、卡顿或错误游戏、平台、区服产生的时间直接计入。达标后等待 20 秒结算缓冲，再读取服务端任务状态，处理符合条件的领取和抽奖。
4. 写请求超时或结果未知时保存待核对状态，不自动重发。用户核对官方结果后重新读取，再决定下一步。

运行中可随时停止任务；停止请求独立于串行操作通道。运行任务、处理请求或存在待核对记录、遗留加速时，客户端配置保持锁定。关闭窗口会收起到托盘，后台队列继续运行；退出时由后端停止任务并保存记录。

[任务租约](../src-tauri/src/lease.rs)与引擎操作锁协调客户端占用及并发请求；[存储层](../src-tauri/src/storage.rs)通过写队列和操作系统文件锁串行持久化。已有状态损坏时返回错误，不将其当作空记录覆盖。
